# Pinned development inputs

forge-rs is vendored at `7f572ed8d0e0a6cfc562571fdbc1ad57441a8438` (MIT, Fexty). The vendored workspace omits cargo-forge from its member list. The converter is supplied separately and fingerprinted. Two source adjustments are carried: Hook adds the native context pointer and uses two 28-byte Jit fields; the ImGui DrawList text wrapper casts byte pointers to the binding's native c_char pointer type so the same wrapper compiles on ARM and the signed-char host. The config/TLS/singleton/Patch/font helpers retain upstream behavior. Hook field offsets and actual native imports are checked against the maintained loader inputs.

Cargo.lock pins runtime/procedural-macro dependencies. Their source and license files live in vendor/crates. The additional sysroot packages supply this nightly's full resolver metadata; only core/alloc/compiler_builtins are built into the ARM runtime. `research/sysroot-Cargo.lock` pins that metadata. Two prebuilt WASI-only objects are omitted from wit-bindgen; its vendor file checksum list describes the retained source subset. WASI libraries are not built for this ARM32 plugin. Runtime component notices are separate from these build-only dependencies.

The pinned C++ oracle and the gateway/asset recipes were copied from this workspace's Damage Numbers r25 source baseline at parent commit `6558bd1`. Oracle code exists only in host tests; it is never linked into damage_numbers_rs.nro. The production gateway is byte-identical to the existing audited assembly. Its GE audit and native declarations are retained under research for reproducible validation. ARM SVC wrappers originate in the project's maintained libnx integration, with the ENTRY macro namespaced to avoid assembler collisions.

The host renderer uses pinned ImGui/cimgui 1.92.8 snapshots and their MIT licenses in vendor/cimgui. Font inputs are Open Sans at Google Fonts revision `9710da1eacb3be272583c3224dcb70f9da6eadbb` and the Forge/Roboto Medium reference for matching metrics. Font licenses and input hashes are preserved. Roboto and the host renderer are development inputs; the runtime ships the renamed Open Sans digit subset and procedural effect data only.

The new Rust implementation, fixtures, recipes and explanatory documentation were written with OpenAI Codex assistance. Procedural artwork uses the existing authored generation recipes; this is code assistance, with no model-generated image or audio asset. The explicit platform disclosure is recorded in DISTRIBUTION.json.
